# CASSEMIRO — Full Website Project Plan

> Source of truth for the CASSEMIRO website. This document combines the business facts, brand direction, content strategy, UX, visual system, immersive interaction direction, technical architecture, SEO, admin system, launch scope, and handoff requirements agreed for the project.

---

# 1. Project vision

Build a premium website for Sérgio Cassemiro's construction company near Sorocaba, São Paulo, Brazil.

This must **not** feel like a normal local-contractor website with a hero, six flat cards, a gallery, and a footer. The public experience should feel **cinematic, immersive, architectural, spatial, interactive, and memorable**.

The desired perception is:

> CASSEMIRO feels like a sophisticated, established construction brand with excellent taste, strong craftsmanship, and decades of real experience.

The website should look more advanced than the current size of the company, but must never fake scale, projects, awards, certifications, clients, or experience.

The website should combine:

- luxury-architecture art direction
- professional construction credibility
- real local relevance
- cinematic construction storytelling
- magical UI movement
- premium typography
- spatial / layered composition
- motion that responds to scroll and cursor
- smooth, choreographed transitions
- strong mobile performance
- a practical admin system for non-technical users

# 10. Signature interaction system

The following ideas should define the public website.

## 10.1 Smooth cinematic scrolling

Use tasteful inertial/smooth scrolling on capable devices.

Scrolling should feel controlled and premium.

Do not make the user fight the page.

## 10.2 Pinned hero construction film

On desktop:

- hero fills the viewport
- the construction progression can scrub with scroll
- text can appear outside the generated media layer
- the viewer feels they are building the house as they scroll

Mobile:

- simplified cinematic version
- lighter video / frame strategy
- reduced scrub complexity
- strong poster fallback

## 10.3 Rotating services catalog

Create a signature service selector.

Possible treatment:

- circular rotating catalog
- perspective carousel
- architectural panels arranged around a virtual axis
- user scrolls/drags to rotate services

Selected service should come forward and reveal:

- title
- short explanation
- CTA

Desktop should feel dimensional.

Mobile should become a smooth swipe/snap experience.

## 10.4 Pinned “Do alicerce ao acabamento” journey

Create a pinned section where construction stages transform as the user scrolls.

Ideas:

- architectural line drawing becomes solid structure
- numbered stages move around the viewport
- layers stack like floors
- text and imagery replace each other without hard section breaks

## 10.5 Horizontal project reel

Real projects can move horizontally while vertical scrolling continues.

Use:

- oversized imagery
- masks
- layered captions
- subtle parallax
- project index

If there are no suitable real projects, hide this experience until real material exists.

## 10.6 Stacked / peeling cards

Use one or two sections where content cards stack in depth and peel away during scroll.

Good candidates:

- values
- project highlights
- process steps

Do not use this for every section.

## 10.7 Picture movement

Images should not simply sit inside static rectangles.

Use selective effects such as:

- parallax crop movement
- slow pan
- clip-path reveal
- scale on scroll
- depth tilt
- image mask expansion
- image moving behind typography
- image moving from small framed state to full bleed

## 10.8 Magnetic buttons

Primary CTA buttons can subtly pull toward the pointer.

Keep movement restrained and accessible.

## 10.9 Cursor interaction

Desktop only.

Optional custom cursor behavior:

- contextual label on draggable areas
- subtle ring or dot
- hover expansion
- image preview on service/project links

Never harm usability.

## 10.10 Architectural particles / atmosphere

Use subtle ambient motion in selected moments:

- construction dust
- tiny light particles
- architectural grid points
- line fragments
- blueprint-style lines

Avoid cheesy starfield effects.

Prefer lightweight canvas/WebGL or CSS depending on complexity.

## 10.11 Morphing transitions

Sections should feel connected.

Examples:

- a bronze line from one section becomes the next section divider
- an image frame expands into the next background
- a concrete panel slides over content
- typography moves behind/through a plane
- service carousel transforms into CTA section

## 10.12 Page transitions

Navigating between major marketing pages should feel deliberate.

Use:

- quick mask wipe
- logo/C monogram transition
- architectural panel slide
- controlled fade + movement

Do not make navigation slow.

## 10.13 Layered typography

Use oversized words in a few places.

Text can move:

- behind images
- in front of images
- across masks
- at different scroll speeds

Maintain readability.

## 10.14 Subtle 3D

True 3D is optional and targeted.

Potential use:

- rotating CASSEMIRO C monogram
- architectural line object
- tiny material/geometry moment
- spatial service selector

Do not turn the entire website into a WebGL scene.

# 22. Recommended technical stack

Goal:

**premium public experience + affordable infrastructure + low maintenance**

- Next.js
- TypeScript

- GSAP + ScrollTrigger for major scroll choreography

- Motion/Framer Motion only for component-level transitions if needed

- Three.js / React Three Fiber only for targeted true-3D moments if they materially improve the experience

- Sentry for error monitoring

Avoid unnecessary infrastructure.

# 23. Motion implementation rules

Use one clear ownership model:

- **GSAP / ScrollTrigger**: pinned scroll scenes, scrubbed sequences, horizontal galleries, complex choreography
- **Lenis**: scrolling only
- **CSS**: hover states, basic 3D perspective, transitions
- **Motion**: simple component enter/exit where it saves complexity
- **R3F/Three.js**: only if a signature true-3D moment needs it

Do not create conflicting animation systems.
